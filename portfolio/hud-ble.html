Project 01 · 2025.07 — 2025.08 (2주)

차량용 HUD 내비게이션 연동 시스템

운전 중 내비게이션 화면을 주시하는 것은 안전 문제로 이어집니다. TMAP의 실시간 주행 데이터를 BLE를 통해 HUD 디바이스로 무선 전송해 운전자가 전방을 보며 내비게이션 정보를 확인할 수 있도록 하는 시스템을 개발했습니다. 2024.08.01 실차 테스트를 완료했습니다.

데이터 플로우: TMAP SDK → SharedFlow → 데이터 변환 → HUD 프로토콜 → BLE 전송
TMAP EDC SDK에서 1초마다 수신되는 속도, TBT 경로 안내, 차선 정보(최대 10차선), SDI를 처리합니다.

멀티 모듈 Clean Architecture 설계

core/bluetooth, core/common, core/designsystem, data, domain, feature 계층으로 분리해 각 레이어의 책임을 명확히 구분했습니다.

왜 BLE 전송에 Queue + Mutex + CompletableDeferred를 조합했는가

BLE GATT write는 비동기로 동작하기 때문에, ACK 응답을 확인하기 전에 다음 패킷을 보내면 데이터가 유실됩니다. 연속 전송 시 패킷 순서도 보장할 수 없었습니다.

AS-IS

write 요청을 순서 없이 연속 전송.
ACK 유실 시 다음 패킷이 그대로 전송됩니다.

TO-BE

Channel 기반 Queue로 순차 처리합니다.
Mutex로 동시 전송을 방지하고, CompletableDeferred로 ACK 확인 후 다음 전송합니다.
50ms 페이싱으로 디바이스 처리 시간을 확보했습니다.

Project 02 · 2025.08.05 — 2025.08.18 (2주)

TMap 기반 네비게이션 앱 프로토타입

상용 내비게이션 SDK와 경로 데이터 API를 활용해 지도 표시, 장소 검색, 경로 안내, 실시간 위치 추적을 제공하는 Android 프로토타입을 설계하고 구현했습니다.

MVI + 멀티모듈로 화면 상태를 관리한 이유

지도, 검색, 경로 안내가 동시에 동작하는 화면에서 상태가 분산되면 디버깅이 어렵습니다. MVI의 Intent/State/Effect 패턴으로 단방향 데이터 플로우를 확립했으며, 기능 추가나 교체 시 영향 범위를 모듈 단위로 최소화했습니다.

포그라운드/백그라운드 위치 추적 전략 분리

액티브 상태에서는 UI 응답성을 우선해 업데이트 주기를 짧게 가져가고 마커 이동을 부드럽게 처리했습니다. 백그라운드에서는 배터리와 정확도의 균형을 위해 주기를 조절하고 포그라운드 서비스를 활용했습니다. 오류, 권한, 네트워크 피드백은 단일 가이드로 통일했습니다.

경로 데이터 파이프라인 모듈화

경로 데이터를 블록 단위로 해석하고 좌표계 변환과 정합성 검증을 거쳐 지도 엔진에서 소비 가능한 모델로 출력하는 파이프라인을 설계했습니다. 트러블슈팅: Base64 인코딩 경로 데이터의 타입 불일치로 장거리 경로가 손상되는 문제를 발견하고 수정했습니다.

Project 03 · 2025.08.3주 — 2025.09.2주 (4주)

Mock Location 앱 — 실차 없이 주행 재현

차량용 내비게이션 개발 환경에서 실제 주행 없이도 위치 기반 기능을 테스트할 수 있는 Android 앱입니다. CSV/로그 파일로 주행 데이터를 재생하거나, 경로 탐색 API 결과로 가상 주행을 시뮬레이션합니다.

실차 없이 현실적인 주행 재현이 가능해져 개발·QA 리드타임이 단축됐습니다.

왜 속도 기반 위치 보간을 직접 구현했는가

로그 파일의 샘플 좌표를 그대로 전송하면 좌표 간격이 불균일해 마커가 튀듯 이동합니다. 입력 경로를 거리 누적으로 정규화한 뒤, 목표 속도와 업데이트 주기에 맞춰 간격 타깃 거리를 계산하고 샘플 좌표 사이를 선형 보간해 자연스러운 이동 궤적을 생성했습니다.

대용량 로그 파싱 시 ANR 해결

대용량 CSV 로그 파일을 한 번에 읽으면 메인 스레드가 블로킹되어 ANR이 발생했습니다. Buffered I/O + 라인 시퀀스 처리와 청크 단위 변환으로 메모리 사용량을 제어했으며, 진행률 콜백과 중도 중단 시 안전 종료/복구 로직을 추가했습니다.

앱 재시작 후에도 위치 주입 연속성 유지

포그라운드 서비스로 백그라운드에서도 좌표를 계속 전송하도록 구현했습니다. 앱 프로세스가 종료되면 서비스 상태가 유실되는 문제는 상태 복원 기능으로 해결해 재시작 후에도 연속성을 유지했습니다.

Working Style

사내 코드를 보호하면서 AI 도구를 활용한 방법

Cursor AI는 프로젝트 전체 컨텍스트를 읽어 코드 제안을 제공하는 구조입니다. 회사 내부 문서와 SDK가 포함된 프로젝트에서 그대로 사용하면 기밀 정보가 외부 모델에 노출될 수 있었습니다.

듀얼 프로젝트 구조를 설계했습니다.
실제 회사 프로젝트는 Android Studio만 사용하고, Cursor AI는 샌드박스 프로젝트에서만 사용했습니다.

워크플로우는 4단계입니다. 회사 코드에서 패턴을 파악하고 → 샌드박스에서 일반화된 버전을 작성한 뒤 → Cursor AI로 샌드박스 코드를 개선하고 → 개선된 패턴을 프로젝트에 수동 적용합니다. .cursorignore로 SDK 파일(*.aar)과 스펙 문서(*.pdf)를 Cursor 인덱싱에서 제외했습니다.

결과적으로 아키텍처 패턴 학습 시간이 70% 단축됐고, 공개 알고리즘(선형 보간, Haversine 거리 계산 등) 구현이 2일에서 4시간으로 줄었습니다. 보안과 생산성을 동시에 확보한 프로세스로, 이후 프로젝트에도 적용 가능한 방법론을 정립했습니다.
